# Native Mac Tab Groups Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build a native macOS menu bar utility that groups windows from different apps into tabs with shared screen bounds and saves group membership across sleep and utility restarts.

**Architecture:** Use SwiftUI for the small menu bar settings/status interface and AppKit for the floating tab strip panel. Use macOS Accessibility APIs to identify, move, resize, and raise external app windows. Persist group metadata in a versioned JSON file in Application Support and reconnect saved records to already-open windows on launch or wake.

**Tech Stack:** Swift, SwiftUI, AppKit, ApplicationServices Accessibility APIs, Quartz window metadata, Codable, XCTest.

---

## Product constraints

- The group is a shared screen rectangle, not a literal parent window containing other apps.
- Only the selected app window should occupy the front of the shared area; switching tabs raises another member window at the same bounds.
- Shift-drag a window onto another to create or extend a group; drag a tab out to remove it.
- Store group records locally. Sleep normally leaves apps and their windows open; reconnect to those windows after wake. On utility relaunch or Mac restart, reconnect only to windows already available. Do not automatically open apps or documents.
- Accessibility permission is required. Some apps may refuse window moves/resizes; duplicate app windows may be ambiguous after a restart.
- Follow the workspace instruction: do not run build, test, lint, typecheck, or other verification commands unless the user explicitly asks. Tests may be authored as part of implementation, but do not execute them without that request.
- Create the project as a macOS SwiftUI app named `TabGroups` in Xcode. Use the default Xcode project layout under `TabGroups/` and set a deployment target supported by the selected Xcode SDK. Keep third-party dependencies out of the first version.

### Task 2: Model groups and persist them

**Files:**
- Create: `TabGroups/Models/WindowReference.swift`
- Create: `TabGroups/Models/TabGroup.swift`
- Create: `TabGroups/Persistence/GroupStore.swift`
- Create: `TabGroupsTests/GroupStoreTests.swift`

**Steps:**

1. Define Codable models for a group ID, display association, shared bounds, ordered window references, and selected member.
2. Define each window reference with bundle identifier, process ID when live, accessibility identifier when available, window title, and last-known bounds. Treat process ID and live window handles as session-only hints.
3. Implement a versioned JSON store under `~/Library/Application Support/TabGroups/groups.json`, creating the directory on first save.
4. Make saves atomic and preserve the last good file if encoding or writing fails.
5. Add unit tests for empty stores, multiple groups, ordering, and unknown/future schema versions. Do not run tests unless explicitly requested.

### Task 3: Add Accessibility window discovery and control

**Files:**
- Create: `TabGroups/WindowControl/AccessibilityPermission.swift`

- Create: `TabGroups/WindowControl/WindowCatalog.swift`
- Create: `TabGroups/WindowControl/WindowController.swift`

**Steps:**

1. Implement a permission status helper using `AXIsProcessTrustedWithOptions` and expose a method to open the Accessibility privacy settings pane.
2. Enumerate running applications and their accessibility windows; read supported title, identifier, position, and size attributes defensively.
3. Wrap AX window operations in an `AXWindow` value that reports unsupported or failed actions instead of assuming every app supports them.
4. Implement move, resize, and raise operations. Check that the requested position and size were accepted, and return the actual bounds when the app constrains them.
5. Implement reconnection scoring: prefer a live PID plus AX identifier in the current session; after restart, match by bundle identifier, AX identifier, title, and approximate prior bounds. Return ambiguous matches for user choice instead of guessing.
6. Add unit tests for matching priority and ambiguous duplicate titles. Do not run tests unless explicitly requested.

### Task 5: Implement grouping and shared resizing

**Files:**
- Create: `TabGroups/Interaction/WindowDragMonitor.swift`
- Create: `TabGroups/Interaction/GroupCoordinator.swift`
- Modify: `TabGroups/WindowControl/WindowController.swift`
- Modify: `TabGroups/TabStrip/TabStripCoordinator.swift`
- Modify: `TabGroups/StatusMenuView.swift`

**Steps:**

1. Monitor global mouse and modifier events only while Accessibility permission is granted; detect Shift-drag and resolve source/drop windows through `WindowCatalog`.
2. On drop, create a group from the two windows or append the dragged window to the target window’s group.
3. Save the initial group bounds from the target window, then move and resize both windows to those bounds and show the strip.
4. On tab selection, bring the chosen window forward and reapply current shared bounds.
5. Observe bounds changes for the selected window and update the group’s stored bounds and strip position without entering a feedback loop.
6. Implement drag-out/removal for a tab and persist all membership/order changes.
7. If permission is missing or the source/drop window cannot be resolved, leave the window untouched and show a concise status message.

### Task 6: Restore groups on launch and wake

**Files:**
- Create: `TabGroups/Lifecycle/WindowRestorer.swift`
- Modify: `TabGroups/TabGroupsApp.swift`
- Modify: `TabGroups/Persistence/GroupStore.swift`
- Modify: `TabGroups/WindowControl/WindowCatalog.swift`

**Steps:**

1. Observe workspace application launch/termination and system wake notifications.
2. On launch and wake, enumerate accessible windows and reconnect group members using the matching policy.
3. Restore the tab strip and shared bounds for groups whose members are available; retain unmatched records for later reassignment.
4. Save updated references and bounds after a successful reconnect.
5. Handle app termination by marking its members unavailable without deleting the saved group.
6. Keep the app from launching member apps or reopening documents automatically.
